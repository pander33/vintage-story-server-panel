# Vintage Story Panel 0.4.0

API access and Prometheus monitoring, stronger agent authentication, scheduled announcements
and a move to .NET 10.

## New

- API tokens in access settings: named tokens, role limits, optional expiration and revocation.
  Only a SHA-256 hash of the secret is stored. Issuance requires password confirmation and
  TOTP when enabled; the secret is displayed once and cleared when the session ends.
- `GET /metrics` for Prometheus, authenticated with a session or a viewer API token.
  Exports server health, telemetry, CPU, memory, disks, players, uptime and backup information
  from data already collected by the panel.
- Scheduled in-game announcements, player history and game-port checks.
- Release preparation with `scripts/release.ps1`, including version and notes preparation,
  local checks and validation of the final commit. See `docs/releasing.md`.

## Changed

- The panel now targets .NET 10. Packages remain self-contained; a separate .NET installation
  for the panel is not required. The installer still prepares the runtime used by the game.
- Windows named-pipe clients verify the daemon process account and use identification-only
  impersonation. Agent build information is included in diagnostics; protocol compatibility
  remains the criterion for accepting requests during an update.
- Sensitive administrative actions require an interactive session even with an admin API token.
  Account generations revoke tokens, and recreating a deleted account does not revive old tokens.
- Dependency restore audits include transitive vulnerabilities; scheduled audits and Dependabot
  cover new advisories and dependency updates.
- Configuration revisions use exact decimal JSON canonicalization, avoiding false changes when
  the game rewrites equivalent numbers or rearranges keys.
- Automation persistence and schedule accounting share synchronization. Failed saves undo
  in-memory edits without overwriting scheduler progress.
- Bounded histories and streamed state files reduce memory use. Provisioning and automation
  services were split into smaller components; catalogue refreshes share cached results.
- Improved host-card layout, log handling, download fallback and connectivity diagnostics.
  Missing-backup and low-disk alerts are sent once and then reminded instead of on every tick.
- Documentation now covers API tokens, Prometheus and access to a home server behind NAT.

## Fixed

- Numeric bracket fields and game log levels are no longer classified as mod names.
- Invalid or out-of-range API-token timestamps no longer break loading or turn an expiring
  token into a permanent one. Issuing a token does not prune other tokens using stale accounts.
- Token-store failures return a service-unavailable response; failed issuance confirmations
  appear in the audit log. Invalid tokens cannot lock out valid clients sharing a NAT address.
- Late API responses cannot expose a previous user's token after logout or populate the next
  user's token list.
- Windows pipe-identity failures preserve the actual system error in diagnostics.

## Updating

Existing .NET panel installations update in place with `vs-panel update` (Linux: use `sudo`;
Windows: use an Administrator terminal). Back up panel state and game worlds before updating.
The previous program version is retained for rollback.

Configuration revision hashes change once on upgrade from 0.3.0 or earlier. The apply tracker
falls back to the configuration file's modification time for the old marker; refresh an open
configuration editor before saving after the upgrade. No manual state migration is required.

For a fresh installation, follow the
[README](https://github.com/ruslan120p/vintage-story-panel-net/blob/v0.4.0/README.md).

## Verification and known limitations

Local checks passed: 1,882 .NET tests, six frontend tests and 22 release-script assertions,
plus Release build, formatting and Git whitespace checks. The release pipeline checks Linux
and Windows and verifies all three installation archives before publication.

Full installation, update, firewall, service and game-operation integration tests on target
Linux and clean Windows machines remain outstanding. A scheduled announcement can still be
sent before an overlapping settings save completes; if that save fails, the already sent
message cannot be rolled back. Use HTTPS or a trusted tunnel for access outside a trusted LAN.
